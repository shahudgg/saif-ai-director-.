## What it is

AntiGem runs two coding agents on your phone:

- **Antigravity (`agy`)**: the app talks to the `agy` language server directly over gRPC.
- **Claude Code**: Anthropic's official `claude` CLI runs inside the app's Linux environment, and the app talks to it over its stream-json protocol, with one CLI process per chat.

You can turn on either agent or both, on first launch or later in **Settings → Agents**. An agent you turn off does not run.

The app reads each agent's structured protocol, not its terminal output. That is how it shows streaming replies, tool approvals, the agent's questions, subagents and file changes as normal chat UI.

## Features

### Agents and chat
- Live streaming replies, collapsible thinking, tool cards, diffs and subagent progress.
- Tool approvals, plan approval and the agent's multiple-choice questions, answered inside the chat.
- Switch model, effort, thinking and permission mode during a chat.

## Download

Get the latest APK from [Releases](https://github.com/santoshkurmi/antigem/releases). There are two build variants:

| Variant | Package name | Needs the Termux app? | Notes |
| :--- | :--- | :---: | :--- |
| **`termux`** (recommended) | `com.termux` | No | Self-contained: the app sets up its own Linux environment. This is the one published in releases. |
| **`standard`** | `com.antigem` | Yes | You run `agy_ide_bridge` inside a separately installed Termux app, and AntiGem connects to it over localhost. Not published; build it yourself from source. |

> [!NOTE]
> The `standard` variant is not deprecated, but it gets little attention because almost nobody uses it. Some features, such as the Browser MCP, may not work in it right now, and it may be dropped in the future. Use the `termux` variant.

> [!IMPORTANT]
> The `termux` variant uses the package name `com.termux`, so it cannot be installed on the same phone as the official Termux app. Uninstall Termux first, or use the `standard` variant.

### Why the package name is `com.termux`

Termux packages are compiled for the fixed path `/data/data/com.termux/files/usr`. An app with any other package name cannot run them directly. It would have to use **proot** to fake that path, and proot slows down every program, or rebuild every package for a new path.

With the package name `com.termux`, AntiGem can install the official Termux bootstrap and use the official Termux package repositories, and everything runs at full native speed. This is the only reason for the name.

### This is not a Termux fork

AntiGem is not a copy or modification of the Termux app. The app was written from scratch. It uses only Termux's open-source **terminal-emulator** and **terminal-view** libraries for drawing the terminal, and the Termux bootstrap and package repositories for the Linux environment. The UI, the agent integrations, the Go bridge, the MCP servers, the plugin system and everything else are AntiGem's own code.

### Termux compatibility

Packages, `apt`/`pkg`, the shell and almost everything else work as in Termux. The exception is **Termux:API**: in Termux you install the separate Termux:API app to get commands for location, SMS and other device features.

AntiGem has a few of these built in:

| Command | Built in |
| :--- | :---: |
| `termux-toast` | ✅ |
| `termux-vibrate` | ✅ |
| `termux-clipboard-get` / `termux-clipboard-set` | ✅ |
| `termux-torch` | ✅ |
| `termux-tts-speak` | ✅ |
| `termux-notification` / `termux-notification-remove` | ✅ |
| `termux-volume` | ✅ |
| `termux-battery-status` | ✅ |
| `termux-open` / `termux-open-url` | ✅ |
| `termux-wake-lock` / `termux-wake-unlock` | ✅ |

Other Termux:API commands are not supported. They will not be added to the app itself, because things like location, SMS and contacts would need many extra Android permissions in AntiGem.

The official Termux:API app does not work with AntiGem either: Android only lets it talk to an app signed with the same key as official Termux, and AntiGem has a different signature. The plan is to build a Termux:API app that works with AntiGem. Once that is done, AntiGem will support almost everything Termux does.

## Create with a model in the app

Add **Custom AntiGem Plugin Developer** from MCP presets and tell the model what extension you want. The model should start with `webview_extension_docs`, then follow [the development loop](developer-mcp.md) to create files, install/update, test and inspect errors. ## Create and install manually

An extension (shown in the app as a custom AntiGem plugin) is a ZIP containing `manifest.json` and a JavaScript background worker, a [`skills/`](skills.md) folder, or both. Include your own dependencies as relative JS files. Do not include AntiGem's runtime files. A ZIP may contain those files directly or one enclosing extension folder.

```json
{
  "manifest_version": 3,
  "id": "hello-mcp",
  "name": "Hello MCP",
  "version": "1.0.0",
  "permissions": ["storage"],
  "background": {"service_worker": "worker.js"},
  "mcp_tools": [{
    "name": "hello",
    "description": "Greet a name and remember how many greetings were made.",
    "inputSchema": {
      "type": "object",
      "properties": {"name": {"type": "string"}},
      "required": ["name"],
      "additionalProperties": false
    }
  }]
}
```

```js
chrome.runtime.onMessage.addListener((message, sender, sendResponse) => {
  if (message.type !== 'mcp_tool_call') return;
  (async () => {
    if (message.tool !== 'hello') throw new Error('Unknown tool');
    if (typeof message.args?.name !== 'string') throw new Error('name is required');
    const {count = 0} = await chrome.storage.local.get('count');
    await chrome.storage.local.set({count: count + 1});
    return {greeting: `Hello ${message.args.name}`, count: count + 1};
  })().then(sendResponse, error => sendResponse({
    isError: true, content: [{type: 'text', text: error.message}]
  }));
  return true;
});
```

ZIP the **contents** of `extension_docs/examples/hello-mcp`, then open **Settings → Custom AntiGem Plugins → Install ZIP**. Choose a folder name. Add its MCP connection through **MCP settings → Custom AntiGem Plugin MCP → choose Hello MCP**. The app fills the URL, stable extension ID and device header.

Optionally add an `icon` (`"icon": "icon.png"` plus a square PNG in the package) so users can recognize the plugin in lists. Give the manifest a `version` (optional, recommended) and raise it with each release: the app shows it on the plugin card and shows installed vs. ZIP version before an update. Updates, reloads and enable/disable actions take effect on the current host. No app restart is required. Reload/update interrupts that extension's active jobs. Persistent `storage.local` survives; worker variables and `storage.session` do not. Avoid editing an extension while a paid generation is being submitted.

Use `chrome.scripting.executeScript` to interact with permitted web pages, `chrome.storage.local` for durable state, and `chrome.runtime` messaging for content contexts. Do not build popups, options pages, side panels or toolbar controls: this platform exposes extensions through MCP only.

To port a Chrome extension, audit its APIs against [the reference](chrome-api.md), package its worker dependencies, declare `mcp_tools`, and handle `mcp_tool_call`. An ordinary Chrome manifest alone does not turn its commands into MCP tools.


=== antigem-master/extensions/README.md ===
# AntiGem browser extensions

Place an unpacked extension at `~/extensions/<folder>/manifest.json`. Extensions provide MCP tools through one app-managed Node host. Workers and content scripts can use the supported Chrome APIs; extension popups, options pages, side panels and toolbar icons are not supported.

The APK bundles the `google-flow` extension. A home-directory extension with the same ID takes precedence over the bundled copy.

The shared runtime is app infrastructure: its source lives in `app/src/main/assets/browser-runtime/`, and the APK extracts it to the app's private `files/browser-runtime/` directory. Nothing in `~/extensions/runtime` is needed. Deleting or editing user extensions does not change the runtime; the app restores its bundled runtime when the app process starts.

The runtime has separate layers: `chrome-api.mjs` defines the extension-facing `chrome.*` API, `chrome-polyfill.mjs` connects worker contexts, `browser-api.mjs` maps browser operations to Android, `devtools.mjs` implements the WebView debugging transport, and `extension-host.mjs` manages workers, storage, messaging and MCP.

## MCP presets

**WebView Extension Developer** is a separate preset for creating extensions. Its 12 tools serve SDK documentation/examples, create and edit drafts, package/install/update live, enable/disable, rename, reload, test and retrieve worker logs. See [the developer workflow](../extension_docs/developer-mcp.md).

Settings → MCP → **WebView Extension MCP** opens a chooser of enabled extensions that declare `mcp_tools`. Add Google Flow to expose only its 65 Flow tools; another extension gets its own independent server. Tool names are scoped to each extension, so two extensions may use the same name.

Each preset connects to `http://127.0.0.1:8865/mcp?extension=EXTENSION_ID` with the `X-Device-Id` header. An MCP connection must select one enabled extension; missing or invalid IDs never expose other extensions. The existing `/google_flow` endpoint remains a Flow-only compatibility alias.

**Settings → WebView Extensions** installs and updates ZIP packages, renames actual folders, and enables, disables or reloads workers live. The browser has no extension management section or extension popup UI. Folder renames preserve the stable MCP ID.

See [extension_docs](../extension_docs/README.md) for the complete implemented API reference, package format, lifecycle, MCP protocol and runnable example.

The original `flow_mcp/` source remains as a compatibility reference and worker smoke test. It is not loaded or bundled as an active extension.


## Supported foundation

- Manifest V3 workers, relative module imports, classic `importScripts`, and Manifest V2 background script arrays.
- Promise and callback API forms, callback-scoped `runtime.lastError`, delayed `sendResponse`, messaging, connections and message ports.
- Persistent per-extension `storage.local`; `storage.session` is memory only. `storage.sync` uses local persistence and does not synchronize to a Google account.
- Tabs, one Android browser window, tab events, zoom, downloads and alarms. Nonvisual action metadata is retained for worker compatibility; UI-opening APIs reject with an explicit error.
- Script injection with Promise results, file injection, CSS injection and content scripts. WebView DevTools provides separate extension worlds and new-document scripts.
- The WebView engine's CDP commands through `chrome.debugger`, including remote objects and file inputs. Unsupported engine commands reject instead of reporting success.
- Permissions and host-pattern checks for page access; extension resource paths are confined to the extension directory.

`chrome.antigem` contains explicit AntiGem additions for automation input locking, local files, downloads and extracting frames. These require the `antigemFiles` permission; ordinary Chrome extensions do not need them.

## Limits and validation

This is a compatibility runtime, not a complete Chrome browser. Multiple desktop windows, browser-native UI APIs, Google-account storage sync, and every Chrome API are not implemented. The engine and app must be running for page automation. Loading a worker successfully does not prove that every workflow in that extension works.

Run regression tests without installing packages:

```sh
node --experimental-vm-modules --test app/src/test/browserextensions/*.test.mjs
```

For a standalone host (the app normally manages it):

```sh
node --experimental-vm-modules /data/user/0/com.termux/files/browser-runtime/extension-host.mjs --serve --root ~/extensions --port 8865 --device-id YOUR_DEVICE_ID
```

Do not run this alongside the app-managed host on the same port. Settings uses the per-extension HTTP endpoint. A manual stdio client can use `--connect http://127.0.0.1:8865 --extension-id google-flow --device-id YOUR_DEVICE_ID` with the private runtime launcher.
