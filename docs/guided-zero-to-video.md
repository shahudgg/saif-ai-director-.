# Guided zero-to-video

The zero-to-video Director now starts with a collapsible brief card. Length, format, style and audience choices update the same `DirectorBrief` used by the existing question flow. An answer to the currently visible question advances it once; other choices are remembered without skipping unrelated questions. The confirmation is refreshed if a choice changes. Brief and per-video voice controls are locked once a scene plan exists or production is running; scene editing is available after the timeline has actually been assembled. The brief can be reopened from the header.

Style thumbnails are **illustrations**, rendered on device by `StyleDNA`, the local scene composer and the Canvas scene renderer for the current brief/aspect. They are not a promise that model-designed scenes will be identical. Actual storyboard cards render their scene graphs.

Narration uses either the app's selected voice (SAIF ADVANCE VOICE by default) or a per-video voice profile. The override is stored with the brief and passed to device synthesis; it does not change the app-wide voice. Samples use device TTS, are queued while the engine initializes, and report initialization, speak and asynchronous engine failures. Exact voice availability and pronunciation depend on the Android speech engine and installed voices.

Music is optional and comes from the Android document picker, not an invented track. The picker retains read permission and checks the selected document for an audio track and measured duration. The Director rechecks access when building or refreshing the timeline. It inserts an editable `AudioItem` at the selected gain, bounded by the shorter of the actual source and the video. It does **not** loop short sources; the UI reports this in production notes. Preview and export use the same fade and narration-ducking gain calculations. Replacing/removing Director music preserves unrelated manual audio; after a plan is ready, changes are staged until **Add to timeline**. Access may still be revoked externally after assembly, in which case device playback/export can fail; choose the file again if needed.

During planning the storyboard receives real scene drafts only after model batches pass validation, layout and uniqueness checks, or after a local graph has been built and validated. Final graphs replace earlier provisional drafts. These transient frames are explicitly marked provisional, are not persisted as a final manifest, and are not applied to the project. Cancellation and a generation epoch prevent late callbacks from repopulating them. Once the real timeline is ready, each unlocked scene card offers an inline instruction that calls the existing validated scene revision pipeline; changed scenes still require **Add to timeline**.

`GuidedBriefOptionsTest` checks metadata/question isolation, bounded music, replacement/removal, manual-audio preservation, ducking and malformed metadata. The Android workflow currently makes unit tests non-blocking. Local Kotlin harnesses exercise actual planning and controller method slices, but do not replace a real Android/Compose, media-provider, TTS, preview or export device test.
