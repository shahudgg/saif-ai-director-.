# Director activity trace

Each director controller owns an in-memory, bounded `AgentActivity` event stream. The UI collects it with lifecycle-aware Compose collection; leaving the screen does not start a second job, and reopening it reconnects to the same controller. Up to 120 recent events and 16,000 characters per response are retained in memory, never written into the project store. Model chunks are coalesced to at most one UI snapshot per 100 ms, with the first and final chunks flushed immediately. Truncation is explicitly labelled.

Stage events record real start/end times. Research, script, scene planning, narration, asset search and accepted/rejected decisions, timeline construction and applying the project are emitted by the real operations. Fractions count completed work or the start of a known batch; an unknown fraction is indeterminate. Activity rows can be expanded/collapsed and show actual elapsed durations and outcomes. Streamed model output is the provider's response, not simulated text. Each transport retry has its own event and output buffer; incomplete attempts are marked retried rather than concatenated with the eventual response.

The scene generator currently produces **declarative JSON**, interpreted by the Canvas renderer; it is not executable source code. The separate MoviePy/FFmpeg modal displays a copyable template only. It cannot run or render Python; use the timeline Export action for real rendering. The older prompt-to-video and voiceover panels previously simulated progress and inserted items without media; their generation controls are now disabled and direct users to the Director instead.

Cancelling the director cancels in-flight model calls, closes blocking SSE reads, ends open trace events as cancelled, and propagates coroutine cancellation through fallback/research/narration paths. Device TTS synthesis is stopped on cancellation. Trace history is session memory rather than durable audit storage, and reopening after process death starts a fresh trace. Screen preview/export and provider-specific behavior still require Android/device testing.
